# SDX AutoPost

Десктопное приложение (Windows, Tkinter) для управления Telegram-ботом
автопостинга. Бот берёт сообщения из топиков специальной группы и
публикует их в привязанные к этим топикам каналы по расписанию —
с очередью, кулдауном и реакциями-статусами.

## Как это работает — концепция

1. Создаётся Telegram-группа с включённой функцией **"Темы" (Topics)**
   — назовём её **г_чат**.
2. Бота добавляют в г_чат и создают в нём **топики** — по одному на
   каждый канал, куда нужно постить.
3. Бота добавляют **администратором** в каждый канал, куда планируется
   постинг (например, к_1, к_2 и т.д.).
4. Через команду `/setup`, отправленную **внутри конкретного топика**,
   администратор бота:
   - выбирает, какому каналу соответствует этот топик;
   - выбирает тип автопостинга:
     - **Фиксированный интервал** — посты выходят строго через N минут
       один за другим;
     - **Диапазон** — каждый следующий пост выходит через случайное
       время в заданном диапазоне (например, 30–55 минут), интервал
       каждый раз новый.
5. После настройки любое сообщение, отправленное разрешённым
   пользователем в этот топик, становится **постом в очереди**:
   - Бот ставит на сообщение реакцию ✍️ ("в очереди").
   - Когда подходит время (кулдаун истёк) — бот публикует его в
     привязанный канал через `copy_message` (без пометки
     "переслано" и без указания автора) и меняет реакцию на 🕊
     ("отправлено").
6. Сообщения из очереди публикуются **строго по одному**, в порядке
   поступления: пока не истёк кулдаун — следующий пост ждёт своей
   очереди, даже если он уже добавлен.

## Структура проекта

| Файл                     | Назначение                                                                 |
|---------------------------|----------------------------------------------------------------------------|
| `app.py`                  | Главное окно приложения (Tkinter): версия, HWID, токен, ID группы, настройки, запуск/остановка бота, сворачивание в трей |
| `hwid_utils.py`            | Получение и хеширование HWID устройства, проверка по списку разрешённых хешей на GitHub |
| `token_store.py`           | Хранение токена Telegram-бота |
| `chat_config_store.py`     | Хранение ID группы-чата с топиками (г_чат) |
| `allowed_users.py`         | Список Telegram-ID пользователей, которым разрешено пользоваться ботом |
| `allowed_channels.py`      | Список ID каналов, доступных для выбора в `/setup` |
| `id_list_store.py`         | Общий помощник для хранения списков ID (используется `allowed_users` и `allowed_channels`) |
| `forum_store.py`           | Привязки "топик → канал" + тип автопостинга + время следующего поста |
| `queue_store.py`           | Очередь постов — отдельный JSON-файл на каждый топик |
| `known_chats_store.py`     | Автоматически отслеживаемый список всех чатов/каналов, где состоит бот |
| `unknown_users_store.py`   | Список пользователей, которые писали боту, но не входят в `allowed_users` |
| `telegram_bot.py`          | Вся логика самого бота: команды, очередь, планировщик автопостинга |
| `build.bat`                | Скрипт сборки `.exe` через PyInstaller |
| `icon.ico` *(опционально)* | Иконка приложения и .exe |

Все вспомогательные `*_store.py` модули хранят данные в виде JSON-файлов
в `%APPDATA%\SDX\autopost\` (подробнее — [ниже](#где-хранятся-данные)).

## Настройка приложения

Все настройки задаются в главном окне `app.py`:

1. **HWID** — хеш устройства, отображается автоматически, только для
   информации/лицензирования (см. [ниже](#проверка-версии-и-hwid-лицензия)).
2. **Токен Telegram-бота** — получить у [@BotFather](https://t.me/BotFather),
   ввести и нажать «Сохранить токен».
3. **ID группы с топиками (г_чат)** — числовой ID группы (обычно
   отрицательный, например `-1001234567890`). Узнать ID можно,
   например, через бота [@getidsbot](https://t.me/getidsbot) или
   переслав любое сообщение из группы боту-хелперу.
4. **⚙ Настройки** → два списка:
   - **Разрешённые пользователи** — Telegram-ID тех, кто может
     пользоваться ботом (управлять настройками и отправлять посты).
     Свой ID можно узнать через [@userinfobot](https://t.me/userinfobot).
   - **Каналы для автопостинга** — ID каналов, которые будут доступны
     для выбора при `/setup` в топике.

После изменения токена/ID группы/списков — бот нужно перезапустить
кнопкой «⏹ Остановить бота» → «▶ Запустить бота», чтобы изменения
подхватились.

## Настройка бота в Telegram

1. Создать бота через [@BotFather](https://t.me/BotFather), получить токен.
2. В **BotFather** включить боту разрешение читать сообщения в группах:
   `/mybots` → выбрать бота → **Bot Settings** → **Group Privacy** →
   **Turn off** (иначе бот не увидит сообщения в топиках).
3. Создать группу, включить **Темы (Topics)** в настройках группы.
4. Добавить бота в группу, выдать права администратора (нужно для
   реакций и корректной работы с топиками).
5. Создать в группе топики — по одному на каждый канал.
6. Добавить бота **администратором** в каждый канал, куда планируется
   постинг (без прав администратора `copy_message` в канал не сработает).
7. В приложении указать токен бота и ID группы, добавить ID каналов
   в настройках, запустить бота.
8. В каждом топике отправить `/setup` и пройти настройку (канал → тип
   автопостинга → интервал).

## Команды бота

Все команды работают **только** в группе г_чат и только для
пользователей из `allowed_users`.

| Команда   | Где вызывать        | Что делает |
|-----------|----------------------|------------|
| `/start`  | в любом месте группы | Показывает список каналов и групп/чатов, где состоит бот. Если пользователь не разрешён — сначала показывает сообщение об отказе в доступе (и запоминает его ID), но список каналов/чатов всё равно показывает. |
| `/setup`  | внутри топика         | Запускает пошаговую настройку: выбор канала → выбор типа автопостинга → ввод интервала. |
| `/unbind` | внутри топика         | Снимает привязку топика к каналу (для исправления ошибки настройки). |

Если пользователь не в `allowed_users`, при `/setup` и `/unbind` бот
отвечает сообщением с его ID и просьбой добавить его в настройках —
и не выполняет действие.

## Реакции-статусы

Бот ставит реакцию на **сообщение пользователя** в топике (не на
служебные сообщения бота):

| Реакция | Значение                          |
|---------|-------------------------------------|
| ✍️      | Сообщение добавлено в очередь        |
| 🕊      | Сообщение опубликовано в канале       |

> Для реакций у бота должны быть права администратора в группе.

## Логика автопостинга

- Каждое сообщение (текст, фото, видео, документ, аудио, голосовое,
  анимация, стикер, видео-кружок), отправленное разрешённым
  пользователем в **привязанный** топик, — это один пост.
- Посты публикуются **строго по одному** и **в порядке поступления**
  (FIFO): пока не истёк кулдаун текущего топика, следующий пост ждёт.
- Кулдаун считается **с момента публикации предыдущего поста**, не с
  момента добавления в очередь.
- Если очередь пуста, а кулдаун ещё не истёк — бот просто ждёт.
  Как только появится новый пост — он выйдет сразу по истечении
  оставшегося кулдауна.
- Фоновый планировщик проверяет все привязанные топики каждые **2
  секунды**.
- **Тип "фиксированный интервал"**: пауза между постами всегда равна
  заданному числу минут.
- **Тип "диапазон"**: при каждой публикации бот заново выбирает
  случайное число секунд из заданного диапазона минут — интервалы
  между постами получаются разными каждый раз.
- Публикация выполняется через `copy_message` — в канале пост
  выглядит как отправленный самим каналом, без пометки "переслано" и
  без указания автора.
- Если публикация не удалась (например, бот не админ в канале) — пост
  остаётся в очереди со статусом `queued`, попытка повторится на
  следующем тике планировщика.

## Где хранятся данные

Все данные приложения и бота хранятся локально в:

```
%APPDATA%\SDX\autopost\
├── token.txt                 — токен бота
├── control_chat.txt          — ID группы-чата (г_чат)
├── allowed_users.json        — разрешённые пользователи
├── allowed_channels.json     — разрешённые каналы
├── topics_config.json        — привязки "топик → канал" + тип автопостинга
├── known_chats.json          — все чаты/каналы, где состоит бот (автотрекинг)
├── unknown_users.json        — пользователи, писавшие боту без доступа
└── queues/
    ├── topic_<id>.json       — очередь постов конкретного топика
    ├── topic_<id>.json
    └── ...
```

Формат очереди одного топика (`queues/topic_<id>.json`):

```json
[
  {
    "message_id": 4821,
    "status": "queued",
    "queued_at": 1735567890.123,
    "sent_at": null
  },
  {
    "message_id": 4825,
    "status": "sent",
    "queued_at": 1735567920.456,
    "sent_at": 1735568040.789
  }
]
```

## Проверка версии и HWID (лицензия)

Приложение при запуске (и повторно перед запуском бота) сверяет свою
версию (`APP_VERSION` в `app.py`) с версией в файле на GitHub:

```
https://raw.githubusercontent.com/belka-developer/sdx-prod/refs/heads/main/auto_post/ver.txt
```

Если версии не совпадают — запуск бота блокируется, приложение просит
обновиться.

Кроме того, перед запуском бота проверяется HWID устройства (хеш
`SHA-256`) на присутствие в списке разрешённых хешей:

```
https://raw.githubusercontent.com/belka-developer/sdx-prod/refs/heads/main/auto_post/uid.txt
```

Хеш HWID отображается в главном окне приложения (кнопка «📋 Копировать»)
— его нужно отправить для регистрации устройства.

## Сборка .exe

1. Сложить все `.py`-файлы проекта в одну папку (см. список в разделе
   [Структура проекта](#структура-проекта)).
2. При желании положить туда же `icon.ico` — он будет автоматически
   использован как иконка приложения и `.exe`.
3. Запустить `build.bat` (двойным кликом или из командной строки).

Скрипт `build.bat`:
- проверяет, что Python установлен и виден в `PATH`;
- проверяет, что все нужные `.py`-файлы на месте;
- устанавливает/обновляет `pyinstaller`, `pyTelegramBotAPI`,
  `pystray`, `pillow`;
- собирает **один файл** `.exe` в режиме `--windowed` (без консоли);
- итоговый файл появляется в `dist\SDX AutoPost.exe`.

Собирать нужно на той же ОС, под которую нужен `.exe` (PyInstaller не
кросс-компилирует — для Windows-сборки скрипт нужно запускать на
Windows).

## Известные ограничения

- Telegram Bot API не даёт метода "показать все чаты, где состоит
  бот" — список в `/start` строится по данным, которые бот сам
  накопил через событие `my_chat_member` (плюс список каналов из
  настроек). Если бот был добавлен в канал/группу до первого запуска
  с этой версией кода, при следующем старте бот попытается
  "досеять" уже известные каналы из настроек — но сторонние группы,
  не указанные нигде, обнаружены не будут, пока в них не произойдёт
  событие изменения статуса бота (добавление/удаление/повышение).
- Для реакций (`✍️` / `🕊`) боту нужны права администратора в группе.
- Для публикации в канал боту нужны права администратора в этом
  канале (`copy_message` иначе вернёт ошибку, и пост останется в
  очереди до следующей попытки).
- В `Group Privacy` бота должно быть выключено ограничение на чтение
  сообщений в группах — иначе бот не увидит сообщения пользователей в
  топиках.
- Управление очередью (просмотр/удаление/пауза отдельных постов) не
  реализовано — по договорённости оставлено минимальным: только
  добавление в очередь и автоматическая публикация.
- Если во время настройки (`/setup`) сразу несколько администраторов
  одновременно проходят диалог выбора канала/типа в разных топиках —
  возможна путаница шагов, так как состояние диалога хранится в
  памяти процесса, а не привязано жёстко к топику.

## Диагностика проблем

**Бот не отвечает вообще**
- Проверьте, что бот запущен в приложении (кнопка "▶ Запустить бота"
  переключилась на "⏹ Остановить бота").
- Проверьте статус версии и статус проверки HWID в приложении — если
  бот не прошёл эти проверки, он не запустится (см. всплывающее окно
  с ошибкой).
- Проверьте, что в BotFather выключен `Group Privacy` для бота.

**Бот отвечает "⛔ У вас нет доступа"**
- Добавьте показанный в сообщении Telegram ID в настройках
  приложения → «⚙ Настройки» → «Разрешённые пользователи», сохраните
  и перезапустите бота.

**Пост не публикуется, реакция не меняется на 🕊**
- Проверьте, что топик привязан к каналу (`/setup` был выполнен
  успешно в этом топике).
- Проверьте, что бот — администратор в целевом канале.
- Проверьте, что кулдаун топика уже истёк (для типа "диапазон" каждый
  раз новый случайный интервал).

**Реакции не появляются вообще**
- Проверьте, что у бота есть права администратора в группе г_чат.

**HWID не проходит проверку**
- Скопируйте хеш HWID кнопкой «📋 Копировать» в приложении и
  отправьте его для добавления в список разрешённых устройств.
